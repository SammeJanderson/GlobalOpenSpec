# Global OpenSpec skills (OpenSpec CLI + skillshare)

OpenSpec workflow skills are **machine-global**, not checked into application repos. One directory is generated by the OpenSpec CLI; [skillshare](https://github.com/runkids/skillshare) syncs those skills to Cursor, Claude Code, and other agents.

## Architecture

| Location | Purpose |
|----------|---------|
| `~/.config/openspec/agent-home/` | OpenSpec writes `.claude/skills/`, `.cursor/skills/`, commands, etc. via `openspec init` / `openspec update` |
| `~/.config/skillshare/skills/` | skillshare global source (symlinks into agent-home skills) |
| Agent-specific dirs | Populated by `skillshare sync` (symlinks or copies) |
| `./openspec/` in each repo | Changes and specs only — **no** `.claude/skills` in git |

## Prerequisites

- Node.js 20.19+ and `npm` (for installing OpenSpec when missing)
- `curl` (for installing skillshare when missing)

The setup script installs **openspec** and **skillshare** automatically if they are not already on your `PATH`.

## One-time machine setup

From this repository (or anywhere on PATH):

```bash
chmod +x scripts/setup-openspec-skills-global.sh
./scripts/setup-openspec-skills-global.sh
```

Optional environment variables:

| Variable | Default | Description |
|----------|---------|-------------|
| `OPENSPEC_AGENT_HOME` | `~/.config/openspec/agent-home` | Where OpenSpec generates skills |
| `OPENSPEC_SKILLS_SOURCE` | `$OPENSPEC_AGENT_HOME/.claude/skills` | Skills bridged into skillshare |
| `SKIP_CLI_INSTALL` | unset | Set to `1` to skip auto-installing openspec/skillshare (fail if missing) |
| `SKILLSHARE_INSTALL_DIR` | `~/.local/bin` | Where to install the skillshare binary (avoids `/usr/local/bin`, which may not exist on macOS) |

The script:

1. Installs `openspec` (`npm install -g @fission-ai/openspec@latest`) and [skillshare](https://github.com/runkids/skillshare) when not found
2. Runs `openspec init <agent-home> --tools all` (first time) or `openspec update <agent-home> --force`
3. Runs `skillshare init` if needed
4. Symlinks each skill from `.claude/skills/` into `~/.config/skillshare/skills/`
5. Runs `skillshare sync`

### Agent home layout (after `openspec init`)

Typical paths under `~/.config/openspec/agent-home/` (exact set depends on `--tools` and OpenSpec version):

```text
openspec/config.yaml
.claude/skills/openspec-propose/SKILL.md
.claude/skills/openspec-apply-change/SKILL.md
.claude/skills/openspec-archive-change/SKILL.md
.claude/skills/openspec-sync-specs/SKILL.md
.claude/skills/openspec-explore/SKILL.md
.claude/commands/opsx/…
.cursor/skills/…          (mirror of workflow skills)
.cursor/commands/…
…                         (other tools when using --tools all)
```

## Per-project setup

In each application repository:

```bash
openspec init --tools none
```

This creates only `openspec/` (config, `changes/`, `specs/`) and **does not** add `.claude/skills` or `.cursor/skills` to the repo.

Use `/opsx:propose`, `/opsx:apply`, etc. via **globally synced** skills.

## Refresh after upgrades

```bash
npm install -g @fission-ai/openspec@latest
./scripts/setup-openspec-skills-global.sh
```

Or manually:

```bash
openspec update ~/.config/openspec/agent-home --force
skillshare sync
```

## Troubleshooting

### `mv: rename ... to /usr/local/bin/: No such file or directory`

The upstream skillshare installer defaults to `/usr/local/bin`, which is missing on many Macs. Re-run the setup script (it installs to `~/.local/bin` by default), or manually:

```bash
mkdir -p ~/.local/bin
export INSTALL_DIR="$HOME/.local/bin"
curl -fsSL https://raw.githubusercontent.com/runkids/skillshare/main/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
```

### Symlinks not allowed

Some filesystems or Windows policies block symlinks. Use copy mode per target:

```bash
skillshare target cursor --mode copy
skillshare target claude --mode copy
skillshare sync
```

See [skillshare documentation](https://github.com/runkids/skillshare) for more targets.

### Skills missing in one agent

```bash
skillshare target list
skillshare sync
```

Ensure the target is enabled in `~/.config/skillshare/config.yaml`.

### Slash commands vs skills (v1)

OpenSpec also generates **opsx slash commands** under `.claude/commands/` and `.cursor/commands/` in the agent home. v1 of this workflow syncs **skills** via skillshare; commands stay in the global agent home. Workflow skills embed the full opsx steps, so skills-only delivery is sufficient for v1. Command sync via skillshare extras may be added later.

## Platform notes

| Platform | OpenSpec agent home | skillshare config |
|----------|---------------------|-------------------|
| macOS / Linux | `~/.config/openspec/agent-home` | `~/.config/skillshare/` |
| Windows | `%USERPROFILE%\.config\openspec\agent-home` (or set `OPENSPEC_AGENT_HOME`) | `%AppData%\skillshare\` — set `SKILLSHARE_CONFIG_DIR` if the setup script is adapted for PowerShell |

On Windows, prefer running skillshare’s PowerShell installer and use copy mode if junctions/symlinks fail.

## Verify global setup

1. Run `./scripts/setup-openspec-skills-global.sh`
2. Create a throwaway directory, run `openspec init --tools none`, confirm no `.claude/skills` in that repo
3. Open Cursor or Claude Code in that directory and confirm OpenSpec skills are available (e.g. propose/apply skills listed)
